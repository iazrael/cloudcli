# 图片预览

基准：2026-10-30

文件树图片、聊天图片附件、输入框图片附件、聊天 Markdown 中的本地/工作区图片，以及文档预览（文件查看器）中解析成功的工作区图片，共用全屏图片查看器。工具栏提供缩小、放大、还原、下载图片和关闭操作。Markdown 内嵌的 HTTP、data 和 blob 图片由浏览器直接加载，不提供点击图片展开入口；聊天中的明确 HTTP 图片链接可点击打开查看器。

下载保存当前图片源的原始内容，缩放和拖动不影响保存结果。保存文件名优先使用文件路径的末段，其次使用标题、替代文字、HTTP 图片地址的文件名；没有名称时使用 `image`。完整 HTTP 地址作为标题时取图片地址的文件名，不含查询参数。文件名中的非法字符替换为下划线，没有扩展名时根据图片的媒体类型补全。

保存通过公共文件保存工具交给浏览器或系统文件分享菜单，支持文件分享的设备可选择保存到文件。处理中下载按钮不可重复触发；失败提示保留在查看器内，用户可以重试。外链图片受来源网站的跨域访问规则限制，能显示不代表能下载。

查看器操作文案：`下载图片`、`正在下载图片`；失败提示：`图片下载失败，请重试；外链图片可能不允许下载。`

代码编辑器的媒体预览属于独立界面，不使用这个全屏查看器。

全屏图片查看器和代码编辑器的图片预览均在底部显示图片的实际像素分辨率（宽 × 高 px），不随缩放变化。图片加载完成后才显示分辨率；切换图片或加载失败时不保留旧值。底部路径完整换行显示，可选中，并提供复制路径按钮和成功、失败反馈。复制复用支持普通 HTTP 页面的剪贴板工具。

路径优先采用入口提供的原始文件路径或资源路径；外链图片显示原始地址，不显示临时签名地址。上传前附件只有浏览器提供的文件名，显示并复制文件名，不推测本机完整路径；只有内嵌字节或临时 Blob 地址且没有路径的图片显示“无文件路径”。相关文案登记在 common 词典的 `imageViewer` 中，复制按钮复用 `fileOperations.copyPath`。

文档预览按文档所在目录解析图片引用：文件查看器预览用被打开文档的目录。相对路径和 `../` 先按该目录归一化，再交给项目文件接口读取；`file://` 与以 `/` 开头的写法按绝对路径处理；项目外的只读文档（例如 Antigravity 计划文档）里的图片走外部只读文件接口。HTTP、data、blob 地址直接交给浏览器加载，仍受来源网站跨域规则限制。路径解析不出来、文件不存在或超出可读范围时，图片位置显示替代文字，不显示破图。

工具输出中的内嵌图片以资源文件保存，聊天记录提供默认折叠的「结果附件」入口，展开后才能加载预览。图片可用现有查看器放大和下载。大文本结果显示预览，并在结果附件中提供「完整输出.txt」下载原文。模型读取的原始工具结果不受展示处理影响，旧会话重新读取时同样适用。

结果附件文案：`结果附件（{{count}}）`、`完整输出.txt`，分别登记在 chat 词典的 `misc.outputAssets` 与 `misc.fullOutput`。

用户提示词不变为结果预览，复制和编辑重发使用完整原文。HTML、PDF 导出内嵌结果图片与全文资源，离线附件可展开和下载。JSON 导出携带资源映射。导出资源读取失败时提示导出失败，用户可修复后重试；完整导出的文件体积包含所有内嵌资源。

聊天 Markdown 的图片引用按来源加载：HTTP、协议相对地址以及既有 Markdown URL 校验允许的其他浏览器图片地址交给浏览器；聊天消息列表向普通回复、流式回复和工具结果统一提供所属项目；相对路径以该项目目录为基准，走项目文件接口；本地绝对路径和本机 `file://` 地址走外部只读文件接口，并传入当前项目标识；若外部接口返回 403 且关联了项目，再由项目文件接口校验并读取同一路径，以覆盖非 Git 项目。绝对路径不依赖目录层级或图片扩展名识别，普通路径文件名中的空格、中文、`#` 和 `?` 保留。路径中的有效百分号编码仅解码一次；文件名中的字面百分号用 `%25` 表示，例如 `a%2520b.png` 指向文件 `a%20b.png`，无效百分号编码原样保留。`file://` 地址按 URL 规则解码。现有 `/assets`、`/static`、`/public`、`/icons`、`/images` 静态目录和 `/favicon`、`/logo` 图片地址保留浏览器加载语义。与静态目录同名的本地绝对路径使用 `file://` 显式引用。文件能否读取由后端现有目录权限校验决定。

聊天图片读取被拒绝、文件丢失、请求失败或图片解码失败时，原位置保留替代文字、具体提示和原始引用，不回退为裸文件路径图片。可加载的引用提供重试；有引用时提供复制路径和复制结果反馈。相对路径缺少项目上下文或引用无法解析时，提示无法解析。切换引用或项目时，不显示上一张图片或其失败状态。

图片加载提示登记在 chat 词典的 `imageLoad` 中：`请重新登录后加载图片。`、`图片不在可读目录内，或没有读取权限。`、`找不到图片文件，可能已被移动或删除。`、`图片加载失败，请检查地址或连接后重试。`、`图片无法显示，文件可能已损坏或格式不受支持。`、`无法解析图片引用，相对路径需要关联项目。`、`路径已复制。`、`复制失败，请选中上方路径手动复制。`。操作按钮复用 common 词典的复制路径和重试文案。

Markdown 文档预览中的本地文件链接（如 `[原图](../../out/image.png)`）与内嵌图片共用文档目录解析规则。普通路径、绝对路径和本机 `file://` 路径都按文档所属项目或外部只读文档的现有规则读取；文件权限仍由后端校验。链接先分离查询参数和片段，再解码一次；文件名中的 `#`、`?` 和字面百分号分别用 `%23`、`%3F`、`%25` 表示。

本地图片链接点击后才读取原图，并在全屏图片查看器中打开；关闭查看器后保留原报告位置，再次打开可复用当前文档内已读取的图片。缩略图作为链接内容时打开链接指向的原图。读取失败时原位置显示原因、解析后的路径和重试入口，不跳转到网站上的同名地址。切换或关闭文档时，关闭图片查看器、中止未完成请求并释放图片资源。本地文件操作使用按钮，避免中键或新标签菜单把磁盘路径当网站 URL 打开。

聊天正文中明确以图片扩展名结尾的地址可点击预览，包括 Markdown 链接、单独的行内代码路径和普通文本中的地址。支持绝对路径、项目相对路径、文件名、`file://` 和 HTTP 图片地址；HTTP 地址可带查询参数和片段。识别 PNG、JPEG、GIF、WebP、SVG、AVIF、BMP、ICO、TIFF 等常见图片扩展名，不猜测无扩展名的地址。普通文本按空白及标点分隔；含空格的绝对路径可用行内代码或 Markdown 链接明确边界。

识别只改变前端显示，不改消息原文，不处理代码块、公式和既有链接内部。本地文件引用的识别范围与图片一致：Markdown 链接和单独的行内代码路径（含 `:line` 行号后缀）都转成链接；路径须含分隔符或带扩展名，含空格的必须是路径锚定写法，纯文本中无边界的路径和命令片段不做猜测，不转链接。聊天中的本地图片引用和本地文件、目录链接先按各自的后端接口批量探测可读性：图片引用复用签名接口，文件和目录链接走 file-tree 的批量存在性接口；明确返回不存在或不可读的引用按原样显示——图片退回普通文字，行内代码保持代码样式——不提供点击入口，也不附加额外样式或提示。探测未完成、相对路径缺少项目上下文或探测临时失败时保持现有可点行为；可点的本地图片引用点击后才加载图片字节，统一打开全屏图片查看器，保留分辨率、路径和复制能力；关闭后仍在原消息位置。会话记录了实际运行的工作树时，相对路径同时按工作树根和项目根两处候选探测，工作树命中优先，两处都不存在才视为不存在；工作树路径必须是项目已登记的工作树才可读，绝对路径沿用现有外部目录读取及项目回退规则。缺少项目、读取失败或无法解码时显示原因与引用，可重试的错误提供重试入口。其他文件链接、目录链接和本机服务代理保持各自的打开方式。

存在性探测的失败结果不缓存，后续渲染重新探测，稍后被创建的文件会恢复为可点；成功结果在同一账号范围内复用。转录列表已虚拟化，探测只发生在挂载的消息行。文档预览（文件查看器）中的链接不做存在性探测，行为不变。

其他本地文件链接通过现有文件查看器打开，目录链接在文件树显示。缺少文档上下文而无法解析的引用只显示文字。外部网址、协议相对地址和邮件链接保留浏览器跳转；单独的 `#片段` 保留当前页面的浏览器锚点语义。提示复用 codeEditor 的预览加载文案、chat 的 `imageLoad` 文案和 common 的重试文案。
