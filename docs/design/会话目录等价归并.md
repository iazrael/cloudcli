# 会话目录等价归并

状态：已批准，实施中（2026-11-18）

## 目标

引擎把会话工作目录规范化成同一目录的另一种写法时（claude CLI ≥ 2.1.327 启动时解析软链，把用户经 `/Users/azrael/workspaces/X` 打开的项目记录成物理路径 `/Volumes/Extenal/Workspaces/X`），会话必须仍归到既有项目，而不是裂出一个同名的"影子项目"。

实证现场：2026-11-18 起 DuskBastion 出现两个同名项目（41+2 会话 vs 2 会话），claude-switch、MirLite 的新转录目录同日物理化——不修则每个项目都会裂。

## 范围

- 新增共享策略 `canonicalizeSessionProjectPath`（`server/modules/providers/shared/sessions/`），claude / codex / cursor 三个文件扫描索引器与 SQLite 骨架（antigravity / zcode / opencode）在 admission 之前调用。
- 既有脏数据不迁移：部署后首次全量重扫时 `createSession` 的 UPDATE 分支按归并后的路径回写会话行，`archiveOrphanedDefaultNamedProject` 自动归档清空后的影子项目行。

## 方案

对引擎上报的目录：

1. `normalizeProjectPath` 规范化；realpath 失败（不存在/断链）→ 原样返回。
2. realpath 结果与输入相同（绝大多数路径）→ 原样返回，不查库。
3. 在**非归档**项目行里找 realpath 等价者：命中且唯一 → 返回该行存储的路径写法；命中多个 → 会话数多者胜（平局保持库内顺序，即先建者）。
4. 无等价项目（全新目录、子目录、worktree 内部）→ 原样返回，行为与现状完全一致。

只合并**精确等价**（realpath 相同），不做前缀包含匹配：子目录会话、worktree 会话归哪个项目由 worktree placement 策略管，本策略不改变任何合法的"不同目录各建项目"行为。

## 验证

- helper 单测：等价双向归并、全新目录原样、不可解析原样、双胞胎按会话数取胜、归档项目不当归并目标。
- claude 同步器集成测试：注册软链路径项目 + 转录 cwd 为物理路径 → 会话落软链项目、不产生影子项目行。
- 先写失败测试钉死缺陷，再实现转绿。
- 跑 providers / database 相关套件 + `npm run typecheck` / `build`。

## 风险

- realpath 对网络挂载盘慢：仅 realpath 发散路径才会走到查库扫描，常规路径快进返回；本项目项目行为本地盘，量小（当前 27 行）。
- 用户手工建的"另一个写法"项目被并掉：只认非归档项目，且归并发生在发现侧，不删任何行；影子行清空后走既有孤儿归档逻辑（默认名才归档，手工命名行保留）。
- codex / cursor / SQLite 骨架当前引擎未规范化目录，接入属同根因预防：假路径测试 short-circuit，无行为变化。
