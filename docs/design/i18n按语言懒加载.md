# i18n 按语言懒加载

状态：已完成

基准：2.16.0 / 2026-10-29

## 目标

移动端（CF 隧道）冷启动的静态资源墙里，i18n 翻译占了 1MB（br 后约 285KB），而用户只
用其中一种语言。改为只加载"当前语言 + en 兜底"，把启动资源砍掉约八成，并把
解析开销从全量语言降到单语言。

## 范围

- `src/modules/i18n/config.ts`：去掉约 115 个静态 JSON import；init 时 resources 置空，
  新增 `initI18n()` / `switchLanguage()`。
- `src/modules/i18n/resources.ts`（新）：`import.meta.glob` 按需加载
  `locales/<lang>/*.json`，纯加载逻辑，不持有 i18n 实例。
- `src/modules/i18n/index.ts`：barrel 暴露 `initI18n` / `switchLanguage`。
- `src/main.tsx`：渲染前 `await initI18n()`。
- `src/modules/i18n/LanguageSelector.tsx`：切换语言改走 `switchLanguage`。
- `vite.config.js`：`i18n-locales` 整块规则改为按语言 `locale-<lang>` 懒 chunk。

## 方案

- 语言检测沿用现状：模块加载时同步读偏好镜像（`getSavedLanguage`）。
- `i18n.init` 保持模块加载时同步调用（`partialBundledLanguages: true`，resources 置空），
  实例先于一切存在；`initI18n()` 负责把当前语言与 en 的 bundle `addResourceBundle`
  进去，**完成后再触发 React 渲染**——渲染时资源必然就绪，`useSuspense` 不会真的
  挂起。
- 运行时切换与跨设备偏好同步（`subscribeToUserPreferences`）统一走 `switchLanguage`：
  先 `ensureLocaleLoaded`（模块级 Set 去重，每语言只加载一次）再 `changeLanguage`，
  保证 `languageChanged` 触发重渲染时 bundle 已就位。持久化仍由现有
  `languageChanged` 监听器单点写入。
- locale 文件只被动态引用，Vite 按 `locale-<lang>` 切成懒 chunk；chunk 位于
  `/assets/`，命中 SW 的 cache-first，新版本首次访问后即缓存。
- 首次访问新版本时，locale chunk 不在 modulepreload 列表里，会在入口模块求值后
  串行拉取一次（单语言约 30–60KB br）；收益是把 285KB 全量翻译移出并行资源墙 +
  省掉 14 份无用语言的解析。

## 验证

- `src/modules/i18n/tests/localeResources.test.ts`：`loadLocaleResources` 只返回请求
  语言 + en；缺失命名空间（如 zh-TW 无 git）不伪造；未知语言只回 en；`switchLanguage`
  加载 bundle 后才切语言、幂等。
- `npm run build:client` 后检查 `dist/assets/`：无 `i18n-locales-*` 整块，出现
  `locale-en-*` / `locale-zh-CN-*` 等懒 chunk；`dist/index.html` 的 modulepreload
  不再包含任何 locale chunk。

## 风险

- 资源加载失败时应用仍需可启动：`initI18n` 内部按语言独立加载、失败降级告警，
  最坏情况界面显示 key 而不是白屏。
- 渲染依赖 `initI18n` 先行，若未来有人在 init 完成前渲染组件，会退化为 key 文本；
  属于可接受的显式契约（本文件为准）。
