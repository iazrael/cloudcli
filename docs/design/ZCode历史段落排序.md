# ZCode 历史段落排序

状态：已实现

## 目标与范围

修复 ZCode 历史回复中思考段落偶尔落在正文后面的问题。只调整历史联表查询及对应回归测试，不改变实时事件和分页接口。

## 方案

同一消息的段落按创建时间、段落 `sequence`、段落 ID 排序。创建时间相同时使用引擎保存的顺序号；顺序号也相同或均为空时仍以 ID 保证稳定顺序。

## 验证与风险

通过 `fetchHistory` 读取隔离 SQLite 数据，验证同时间且 ID 顺序相反的思考与正文按顺序号显示，并检查分页顺序和空顺序号的稳定排序。执行现有 ZCode 会话与子代理测试、类型检查及构建。仅影响同一消息内创建时间相同的段落排序，不修改数据库。
