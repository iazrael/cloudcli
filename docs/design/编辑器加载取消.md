# 编辑器加载取消

状态：已实现

## 问题

代码编辑器打开文本文件时，加载中界面（`CodeEditorLoadingState`）只有转圈提示，没有关闭按钮，也没有任何退出方式：

- 桌面端可以按 Esc 退出（快捷键监听在加载分支之前注册，加载中依然生效），但用户不易发现。
- 移动端（PWA）没有键盘，加载大文件时（如几 MB 的 HTML）整个屏幕被加载页占满，用户只能干等网络传输完成，无法取消。

## 目标

加载中界面提供可见的"取消"操作：点击后立即关闭编辑器，并中止仍在进行的文件读取请求，不再继续浪费流量和内存。

## 范围

只处理文本文件加载路径。媒体预览（`CodeEditorMediaPreview`）加载中仍保留头部关闭按钮，已经可以退出，不在本次范围。

## 方案

1. `src/shared/api.ts`：`api.readFile` 与 `readExternalFile` 增加可选 `options` 参数（透传 `RequestInit`，主要是 `signal`），签名保持向后兼容。
2. `useCodeEditorDocument`：每次加载创建 `AbortController`，把 `signal` 传给读取请求；effect 清理（编辑器关闭、切换文件）时 `abort()`。被中止的读取在 catch 中按 `signal.aborted` 静默返回，不当作加载错误上报。
3. `CodeEditorLoadingState`：新增 `onCancel` 与 `cancelLabel`，在转圈提示下方渲染取消按钮。
4. `CodeEditor`：把 `requestClose` 作为 `onCancel` 传入（加载中缓冲区必然为空，不会触发未保存确认，直接关闭）。
5. i18n：各语言 `codeEditor.json` 的 `actions` 增加 `cancel`。

取消即关闭编辑器（而非停留展示"已取消"）：编辑器卸载本身就会触发清理中止请求，不需要额外取消通道。

## 验证

- `src/modules/code-editor/tests/editorLoadCancel.test.tsx`：
  - 读取进行中显示取消按钮，点击后调用 `onClose` 且请求的 `AbortSignal` 已中止。
  - 切换文件时，上一个文件的在途读取被中止。
  - 被中止的读取不产生加载错误。
- `npm run test:client`、`npm run typecheck`、`npm run lint`、`npm run build:client`。

## 风险

- 中止请求后服务端可能仍在读文件并序列化响应，客户端断开即止，属可接受的浪费。
- `requestClose` 在加载中不会命中未保存确认（缓冲区为空），行为与 Esc 一致。
