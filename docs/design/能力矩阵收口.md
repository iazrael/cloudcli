# 能力矩阵收口（阶段 1d）

> 状态：1d-1、1d-2 均已实施（2026-09-18）
> 目标：前端不再按引擎名分支判断「这家能不能做某事」；做不到就是矩阵里的一个 `false`

## 现状勘察

后端已有一套设计得不错的两层结构，问题不在结构，在覆盖面和边界。

- `provider-capabilities.catalog.ts` 放**推导不出来的静态事实**（权限模式、默认模型、附件/中止/effort）
- `provider-capabilities.service.ts` 从**已注册切面推导**其余能力——切面在即能力在，加减切面自动翻转，不用改表

前端有 26 处按引擎名硬分支。逐个看过之后分成三类，只有前两类该动。

### 甲类：矩阵缺项，前端只好自己硬编码

**套餐用量**。`src/modules/chat/utils/providerQuota.ts` 写死了
`QUOTA_PROVIDERS = ['antigravity', 'codex', 'zcode']`，而矩阵里压根没有 quota 这一项。
这就是「claude 套餐用量没实现」的真实来路——不是没设计，是能力表没这一栏，于是谁要用谁自己列名单。

值得注意的是**切面早就存在**：`provider-token-usage.service.ts` 是按
`provider.auth.getQuota?.()` 分发的。也就是说推导只需要一行
`typeof provider.auth.getQuota === 'function'`，和现有 `supportsTokenUsage` 完全同构。
缺的从来不是机制，是有人把这一栏加上。

**MCP 配置字段**。前端 5 处 `provider === 'codex'` 决定是否显示 env vars、
bearer token、HTTP headers 字段。后端 `McpProvider` 已经声明了 `supportedScopes`
与 `supportedTransports`，却没有声明字段级支持，前端只能按引擎名猜。

**配额展示形态**。`providerQuota.ts` 的 `bucketPartitioned = codex || zcode`，
以及 `CommandResultModal` 里 codex 独有的一段。这类「这家的配额数据长什么样」
应当由配额载荷自我描述，而不是前端记住哪家是哪样。

### 乙类：归一化没做干净，漏到了前端

这两处不是能力问题，是**适配器没把差异吃掉**，于是差异一路漏到 React 组件里。

- `src/shared/utils.ts` 的 `getSessionTitle`：Cursor 会话带 `name`，其余引擎带 `summary`，
  前端因此要认得 Cursor。**该由 Cursor 适配器把 `name` 映射成 `summary`。**
- `src/modules/chat/transcript/MessageComponent.tsx`：Codex 的 assistant 正文外面裹了一层
  "proposed plan" 信封，前端在渲染时剥。**该在 Codex 归一化时剥掉**，
  一个跨引擎共用的渲染组件不应该认得任何一家的私有包装。

### 丙类：本就因引擎而异，不该进矩阵

`LLMProviderLogo.tsx`（6 处）与 `ProviderLoginModal.tsx`（12 处）是 Logo 与登录说明文案。
这是**展示数据**，不是能力。把它们塞进能力矩阵只会让矩阵变成杂物间。
如果嫌 if 链难看，那是查找表重构，与本文无关。

## 切片

### 1d-1 能力补全（本次提案）

1. `ProviderCapabilities` 增加 `supportsQuota`，由 `auth.getQuota` 推导，沿用既有推导写法。
2. 配额载荷自述展示形态，取代前端的 `bucketPartitioned` 与 codex 专有分支。
3. `McpProvider` 声明字段级支持，能力矩阵透出，前端 MCP 表单按声明渲染。
4. 前端删除 `QUOTA_PROVIDERS` 与上述 9 处分支，改读矩阵。
5. `provider-capabilities.test.ts` 的基线随之更新——它本来就是用来把能力变化变成一次可审阅的差异的。

**Claude 的套餐用量本次不实现**。1d-1 要做的是让「没有」成为矩阵里一个明确的
`supportsQuota: false`，而不是一个散落在前端的名单。真去接 Claude 的用量接口是另一件事，
做完这一片之后它会变成「给 claude 的 auth 切面加一个 `getQuota`」，不需要再碰前端。

### 1d-2 归一化回收

把乙类两处差异收回各自适配器：Cursor 的会话标题、Codex 的 plan 信封。

这一片改的是**行为**而不是类型，所以每处都先补一个适配器层的测试钉住归一化结果，
再删前端分支。与 1d-1 无依赖关系，但**不建议同一次提交**——
类型/声明层的改动和归一化行为的改动混在一起，回归时不好二分定位。

## 1d-1 的验收

- `grep "QUOTA_PROVIDERS"` 无结果；前端 `provider === 'xxx'` 分支从 26 处降到 17 处（剩余全为丙类）
- 给任一引擎的 auth 切面加上或去掉 `getQuota`，矩阵的 `supportsQuota` 自动跟随，无需改任何表
- 能力基线测试、跨树 parity 测试、前后端 typecheck 与全量测试通过
