# 模型上下文窗口来源

状态:实施中(2026-11-24)

## 目标

Claude 会话走 Anthropic 兼容网关（例如 `ANTHROPIC_BASE_URL=https://opencode.ai/inference/go/anthropic`）时，SDK 的 `result.modelUsage` 不带 `contextWindow`，claude 侧只能回退全局 `CONTEXT_WINDOW`（默认 160K）。实际模型（`deepseek-v4.1-flash` 等）窗口是 1M，于是上下文占比被放大数倍，输入框里的窗口分母和用量比例都失真。

目标：SDK 不报窗口时，仍能按会话实际运行的模型拿到可信窗口；拿不到时保持现有回退，不猜测。

## 范围

- 新增 `server/modules/providers/services/model-context-window.service.ts`：解析显式配置，并读本机 models.dev 目录（OpenCode CLI 缓存在 `opencode.db` 的 `kv` 里）按模型 id 查 `limit.context`。
- `claude-runtime.provider.ts` 与 `services/claude-usage.ts` 的窗口解析改用该服务；实时预算与历史回读两条路径一致。
- `opencode-models.provider.ts` 的目录读取改为复用同一服务，避免两份缓存解析。
- 不改其他 provider 的窗口来源，不改 `CONTEXT_WINDOW` 现有语义。

## 方案

窗口解析优先级（从高到低）：

1. SDK 本轮报告的 `result.modelUsage[model].contextWindow`（现有行为）。
2. `MODEL_CONTEXT_WINDOWS` 显式配置：`model=window,model2=window2`，模型 id 精确匹配。
3. 本机 models.dev 目录缓存：模型 id 先试 `opencode-go/<id>`、`opencode/<id>`；再试其他家族，只有所有命中项窗口一致时才采用，避免同名模型跨家族窗口不同造成误判。
4. `CONTEXT_WINDOW` 全局配置（现有回退）。
5. 默认 160K（现有行为）。

目录读取按数据库文件 `mtime` 缓存解析结果，模型目录被 OpenCode 刷新后自动失效；读不到数据库、`kv` 或目标模型都返回 null。

会话模型 id 的来源：实时路径用流里的主线程 assistant `message.model`；历史路径用转录里最后一条主线程 assistant 行的 `model`（累加器里记录，子代理行不覆盖）。

## 验证

- `model-context-window.test.ts`：显式配置覆盖、家族优先级、同名跨家族冲突不猜、无目录返回 null。
- `claude-context-window.test.ts` 增补：SDK 不报窗口时实时预算与历史回读分别命中显式配置和本机目录。
- 既有 `claude-context-window` / `claude-token-budget` / `opencode-models` 测试回归。
- `npm run build`、`npm run typecheck`、`npm run lint`。

## 风险

- 本机没有 OpenCode 或目录缓存缺失时行为不变（回退全局配置）。
- 同名模型跨家族窗口不一致时不采用目录值，宁可回退也不给错数。
- 目录解析缓存按 mtime 失效，不会读到过期条目；单次解析 13MB JSON 只发生在首次或目录更新后。
