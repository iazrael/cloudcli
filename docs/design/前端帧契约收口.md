# 前端帧契约收口（阶段 2）

> 状态：2a 已实施（2026-09-18）；2b 待实施
> 前置：阶段 1（1a 契约收口 / 1b 运行时闸门 / 1c 构造侧判别 / 1d 能力矩阵）已实施
> 目标：让前端接收帧这一侧也有编译期约束，而不是靠索引签名把一切当 `unknown` 放行

## 现状勘察

原计划这一步是「给客户端的 `NormalizedMessage` 补收窄谓词」。摸完之后结论要改：
**前端真正松的不是时间线行，是进来的帧本身。**

### `ServerEvent` 等于没有类型

```ts
export type ServerEvent = {
  kind?: ServerEventKind | 'websocket_reconnected';
  type?: string;
  sessionId?: string;
  seq?: number;
  [key: string]: unknown;
};
```

`sessionTimelineStore.ts` 从它身上读 **22 个不同字段**——`anchorId`、`lastSeq`、`stale`、
`isProcessing`、`pendingPermissions`、`code`、`error`、`tokenBudget`……
除去声明的四个，其余**全部命中索引签名**，读错名字、读错 kind 上不存在的字段，编译器一律不管。

这正是 1a 在 `NormalizedMessage` 上刚拆掉的那套东西，只是位置上移了一层。

### 三种网关帧从未声明

`ServerEventKind` 列了五种网关事件，但只有两种有载荷类型
（`SessionUpsertedEvent`、`SessionRemovedEvent`），另外三种是裸的：

| 帧 | 实际载荷（读自服务端产出点） |
| --- | --- |
| `chat_subscribed` | `sessionId`、`isProcessing`、`lastSeq`、`stale`、`pendingPermissions`、`timestamp` |
| `protocol_error` | `code`、`error`、`sessionId`（可空）、`timestamp` |
| `loading_progress` | `phase`、`current`、`total`、`currentProject?` |

`loading_progress` 还是老毛病：服务端叫 `ProgressUpdate`（`phase: 'loading' \| 'complete'`），
前端叫 `LoadingProgress`（`phase?: string` 且带索引签名），又是一对会漂的副本。

### 相比之下时间线行已经不松

客户端的 `NormalizedMessage` 没有索引签名，字段来自协议。
给它补收窄谓词仍有价值，但它拦不住的东西，远少于 `ServerEvent` 正在放行的东西。

## 切片

### 2a 帧类型化（本次提案，建议先做）

1. 三种网关帧的载荷进协议：`ChatSubscribedEvent`、`ProtocolErrorEvent`、`LoadingProgressEvent`。
   `loading_progress` 顺带消灭前后端两份副本，`phase` 收敛成服务端那个二值联合。
2. `ServerEvent` 改成按 `kind` 判别的联合：消息类 kind 走 `NormalizedMessage` 形状，
   网关类 kind 走各自载荷，外加客户端本地合成的 `websocket_reconnected`。
3. **删掉 `ServerEvent` 的索引签名**。
4. 修因此暴露的读取点——早先实验显示约 29 处，全部是「这个字段属于哪种帧」没说清楚导致的。
   逐处用 kind 收窄后再读。

做完之后，`msg.lastSeq` 只有在确定是 `chat_subscribed` 之后才读得到。

### 2b 时间线行的收窄谓词

给客户端 `NormalizedMessage` 补 16 个谓词（协议的 15 种 kind + 客户端自造的
`interactive_prompt`），复用 `MessageFieldsByKind` 并叠加客户端本地字段
（`replacesAnchorId`、`replacesAfterRowCount`）。

前端有 67 处 `kind === '...'` 分支，`useChatMessages` 一个 switch 就 14 个 case，
按需迁移，不做一次性替换——与 1c 在服务端的做法一致。

**2a 先于 2b**：帧是入口，时间线行是帧落表之后的产物；入口没类型时，
给下游补收窄属于从中间开始修。

## 2a 的验收

- `grep "\[key: string\]" src/shared/types.ts` 在 `ServerEvent` 上无结果
- 读一个当前 kind 不存在的帧字段**编译失败**（以一次临时改动实测证明）
- `loading_progress` 只有一处定义，`phase` 两端一致
- 前后端 typecheck、全量测试、构建通过；lint 零新增告警
