# 文件树长按上下文菜单（移动端）

状态：已实现，刷新即生效（纯前端）

基准：main @ 2026-11-21

## 目标

触屏设备上长按项目文件树的文件/文件夹行，弹出与桌面右键相同的 `FileContextMenu`（删除入口目前只存在于该菜单），手机端不再无删除入口。

## 现状

- 菜单组件 `src/modules/file-tree/FileContextMenu.tsx` 只由 `onContextMenu`（右键）触发，定位、菜单项、外部点击/Esc 关闭、键盘导航均已完备。
- iOS Safari 长按普通元素不派发 `contextmenu`，Android Chrome 会派发但同时弹系统行为——手机端实际没有任何入口。

## 方案

在 `FileContextMenu` 的包裹层加触屏长按检测，复用既有菜单开合逻辑，桌面行为零改动：

1. `onTouchStart` 记录触点并起 500ms 定时器；`onTouchMove` 位移超过 10px（滚动）取消；`onTouchCancel`/`onTouchEnd` 清定时器。
2. 定时器到点在触点打开菜单（与右键同一 `calculateViewportSafePosition`）。
3. 长按后松手不得触发行的 `onClick`（展开/打开文件）：touchend `preventDefault` 阻止合成 click，`onClickCapture` 兜底拦截（React 对 touchstart/move 是 passive，touchend 之外再兜一层）。
4. 包裹层加 `WebkitTouchCallout: none` 抑制 iOS 长按系统呼出；Android 的系统 `contextmenu` 事件与定时器都幂等地调用同一打开函数，不双开。

时长 500ms、位移阈值 10px 为组件私有常量，不进 shared。

## 验证

- 新增 `src/modules/file-tree/tests/FileContextMenu.test.tsx`（vitest + fake timers）：
  长按打开菜单并显示删除项；滚动/提前松手不打开；长按后不触发行点击；右键路径回归。
- `npm run test:client`（file-tree 相关套件）、`build:client`、`typecheck`、`lint`。

## 风险

- 触屏笔记本上鼠标快速点按不受影响（未达 500ms）；长按左键 500ms 会开菜单，属合理触屏行为。
- Android 系统 contextmenu 与自检测双触发已幂等处理；若个别 ROM 长按仍弹系统选词，`select-none`（行外层已有）+ `WebkitTouchCallout` 覆盖主流场景。
