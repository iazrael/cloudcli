# 通知内容接线（完成通知带回复摘要 + 失败错误跨重载一致）

> 状态：已实施（新增/受影响套件全绿：providers 1648/1649 含 1 项既有夹具 skip、websocket 118/118、notifications/websocket/database 定向文件全过；typecheck/build/lint 通过；docs/core 两篇已同步。待真机推送验收与独立审查）。第二轮补丁（摘要污染与段语义，见文末）：已实施。
> 基准：v2.23.0 / 2026-11-22
> 分支：`fix/notification-content-wiring`（第二轮：`fix/push-preview-pollution`）

## 目标

1. 回合正常完成时，离线推送正文直接携带本回合最后一条助手回复摘要（现状只有裸状态词 `Codex: completed`，参见 [[release-one-stop-pipeline]] 无关，现场截图见 2026-11-22 会话）。
2. 回合失败时，会话重载后时间线显示的错误与推送里的最终错误一致（现状：推送带 agy 最终错误原文，重载后只剩转录里逐次重试的原始行折叠结果）。
3. 通知 provider 前缀补齐：antigravity/zcode/opencode 不再兜底显示 "Assistant"。

## 现场与证据（2026-11-22）

- **完成通知**：`buildNotificationPayload` 把 runtime 传的原始 `stopReason` 直接塞进正文；五家 runtime（antigravity/codex/claude/zcode/opencode）全部 12 个 `notifyRunStopped` 调用点只传 `stopReason: 'completed'|'aborted'`，无一携带内容。
- **失败通知**：推送文本 = 直播链路转发的引擎最终错误原文。实锤：agy 日志 `log/cli-20261122_002158.log:183` `Print mode: run ended with error and no response: Our servers are experiencing high traffic right now… (UNAVAILABLE (code 503): …)`。
- **重载时间线**：fetchHistory 从 agy brain 转录 jsonl 重建；转录只有逐次重试的 `API error (attempt N)` 行（9 条），**agy 从不把最终错误写进转录**，cloudcli 把它们折叠成一条并加 `(failed after N attempts)` 后缀（antigravity-sessions.provider ERROR_MESSAGE 分支）。直播的详细错误卡不落任何存储（应用库无消息表），刷新即丢。
- **数据通道**：`ChatSessionWriter.send()` 是五家引擎全部出站消息的必经咽喉（writer 按 run 构造，`decorateOutboundEvent` 已回填 app session id），文本行形状 `kind:'text' + role:'assistant' + content`。

## 方案

### 1. 回复摘要（一处覆盖五家，runtime 零改动）

- 新增 `server/modules/notifications/services/run-notification-content.service.ts`：按 app session id 的有界内存登记表（FIFO 上限 256 条，写入即截断 300 字符），`rememberSessionReplyPreview` / `getSessionReplyPreview`。websocket → notifications 本就是单向依赖，无环。
- `ChatSessionWriter` 新增可选构造参数 `appSessionId`：run 注册表构造 run writer 时传入；构造时清空该会话的旧摘要（防跨回合串味），`send()` 里对 `kind:'text' && role:'assistant'` 且正文可见（`hasVisibleText`，防 U+200B 空行）的行更新摘要。session channel 级 writer（非 run）不传不记。
- `buildNotificationPayload` 的 `run.stopped` 分支：有摘要时 `completed` → 正文 = 摘要（折叠空白、截 160 字符），`aborted` → 正文 = `Stopped — <摘要>`；无摘要回退现状。`run.failed` 正文不变（错误文本本身就是内容）。

### 2. 失败错误落库 + agy 历史替换

- 新表 `session_turn_failures`（PK=session_id，一会话一行最新失败）：`provider` / `error_text` / `failed_at`。行数有界（每会话至多一行）。
- 新仓库 `server/modules/database/repositories/session-turn-failures.ts`：`recordTurnFailure`（upsert）/`getTurnFailure`/`deleteTurnFailure`。
- `notifyRunFailed`（编排层）把规范化到 app session id 的失败文本落库，独立于推送偏好开关——它是数据不是通知。
- antigravity `fetchHistory` 后处理：末行是 kind `error` 且库里失败记录新于该行时间戳时，用 `库内错误文本 (failed after N attempts)`（N 取自折叠行自带后缀）替换其正文；无记录或记录更旧则不动。幂等，直播路径不受影响。其余引擎转录自带错误行，不做替换（避免双写重复）。

### 3. provider 标签

`PROVIDER_LABELS` 补 `antigravity: 'Antigravity'`、`zcode: 'ZCode'`、`opencode: 'OpenCode'`。

## 验证

- 单测先行：登记表（记忆/封顶/重置）、payload 分支（completed+摘要 / aborted / 无摘要回退 / failed 不变）、writer 采集（记助手文本、忽略用户与错误行、构造即清旧）、失败仓库 upsert、agy fetchHistory 替换三态（替换/无记录不动/记录过旧不动）。
- `npm run build` / `typecheck` / 相关套件全绿后真机验收：手机锁屏收"完成"推送看摘要；agy 503 失败后刷新会话看详细错误。

## 风险

- 推送正文含回复内容 → 锁屏可见性提高。本应用推送本就带会话名与完整错误文本，风险量级一致；如需隐私开关另立任务。
- 登记表为内存态：服务器重启后完成推送回退裸状态词（失败文本已落库不受影响）。
- `notifyRunFailed` 落库为每会话一行 upsert，无迁移数据回填需求；会话删除后可能残留孤儿行（uuid 键、体积极小，不做级联清理）。

## 后续补丁：stream_delta 型引擎需运行时侧记录（2026-11-22）

方案一节"一处覆盖五家，runtime 零改动"对**只发 `stream_delta` 行、不发 `text` 行**的引擎不成立——writer 侧捕获看不见它们的回复正文，完成推送回退裸状态词。这类引擎照 antigravity 先例（`22dce2cf`，运行时泵累积回复并调 `rememberSessionReplyPreview`）在运行时侧自行记录：

- **antigravity**：ACP 泵已接（见 [[agyACP运行时]]）。
- **zcode**：直播流回复正文只有 `stream_delta`（`kind:'text'` 仅压缩摘要）；run writer 构造时清旧摘要的既有机制不变，事件监听循环里累积回复并按 app session id 写入注册表。静默超时转后台 watcher 后，续流仍走同一监听闭包，摘要持续更新到真完成。

## 第二轮补丁：摘要污染与段语义统一（2026-11-23）

摘要上线后逐引擎排查发现三处污染与一处语义不一致，一并修复：

1. **外轮次文本污染（zcode）**：监听循环只按 turn 归属过滤 terminal 消息，`stream_delta` 的拼接没有归属过滤——prompt 抢占引擎自启回合（`startNow` 取消排队回合）时，旧回合收尾文本拼进摘要，推送开头是旧回合文字。修复：拼接与段重置都只认 `turnOwner === 'own'`（`zcode-runtime.provider.ts`）。代价：极端竞态下 own turn 的 delta 抢在 turn.started 与 ack 之前被判 `undecided` 会漏记该段开头——宁缺勿错，漏记只回退裸状态词或上一段。
2. **子代理文本污染（writer 一处覆盖五家）**：codex 子代理线程行（`emitCodexAgentItem`）、opencode 子代理帧（`tieToCard`）、antigravity agent-tail、claude SDK 子代理流量都把带 `parentToolUseId` 的 `text` 行送进 writer，采集条件不看该字段——后台子代理最后完成时推送带的是子代理的回答。修复：writer 采集排除带 `parentToolUseId` 的行（`chat-session-writer.service.ts`）。已逐一核对五家：主线程回复行在任何引擎都不带该字段。
3. **压缩摘要覆盖**：zcode 与 claude 的压缩摘要是 `kind:'text' role:'assistant'` 行（`isCompactSummary`），writer 采集把它当回复。修复：采集排除 `isCompactSummary` 行。
4. **段语义统一**：writer 侧引擎（codex/claude/opencode）推送显示**最后一段**的开头（last text row wins）；拼接型引擎（zcode/antigravity）原本显示全部拼接的开头，多段回复时推送是开场白。修复：拼接在段边界（`stream_end` 行，antigravity 由 ACP translator 的 segment 关闭产出、zcode 由 `text_start`/`text_end` 归一产出）重置本地累积串，注册表保留最后一次写入即最后一段；边界落在 `text_start` 侧还是 `text_end` 侧不影响注册表结果。

### 验证

- zcode：`preempt` 桩模式断言摘要恰为 `user reply`（外轮次文本不进摘要）；新增 `segments` 桩模式断言摘要恰为第二段。
- antigravity：新增 `acp-two-segments` 桩模式断言摘要恰为第二段。
- writer：带 `parentToolUseId` 的 text 行与 `isCompactSummary` 行不更新摘要。
