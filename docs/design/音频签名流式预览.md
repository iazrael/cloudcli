# 音频签名流式预览

状态：已实施，待部署验证（基准：main@1d04b057，2026-11-16）

## 目标

编辑器里的音频文件预览改走图片那套签名 URL 机制，`<audio>` 由浏览器原生边下边播，播放器立即出现；不再像现在这样把整个文件下载成 blob 后才显示。

背景：手机经隧道（上行 ~150KB/s）打开 5.5MB wav，旧整文件 blob 方案要干等 40 秒且只有一行"加载中"。

## 范围

改两处：

1. `server/modules/media/image-media-files.service.ts`：票据签发的 MIME 闸门从"仅图片"放开到"图片 + 音频"。
2. `src/modules/code-editor/CodeEditorMediaPreview.tsx`：`kind === 'audio'` 与图片共用 `useSignedImage` 签名 URL；video/PDF 维持 blob 路径（PDF 有 magic-byte 校验需求）。

配套：两端测试各补音频用例。

## 方案

### 服务端（签发放开）

- `IMAGE_TYPES` 显式集合继续管图片（SVG 有脚本风险，必须白名单、不能放宽）。
- 音频用 `contentType.startsWith('audio/')` 放行：MIME 来自 mime-types 按扩展名查表，路径已过项目/外部根白名单解析；音频 MIME 无脚本语义，响应已有 `nosniff` + CSP sandbox 兜底。
- 票据端点（`POST /api/media/signed-urls` 签发、`GET /api/media/signed?ticket=` 读字节）零改动：机制本就是通用的 source→resolve→签名→流式。

### 前端（音频走签名 URL）

- `CodeEditorMediaPreview` 里把 `useSignedMedia` 的启用条件从 `kind === 'image'` 扩为 image/audio，音频与图片同源（project/external 两分支照抄）。
- 音频渲染仍是 `<audio src controls>`，src 从 blob URL 换成签名 URL；票据获取失败显示既有错误态 + 重试。
- blob 加载 effect 对 image/audio 提前返回；video/pdf 原样。

## 已知取舍（不做）

- **Range/206**：媒体路由不支持 Range，浏览器对无 Range 的 200 音频仍可边下边播；seek 到未缓冲位置会重拉全量，隧道场景依然慢。后续要支持再加 206/Content-Range。
- **视频**：同机制可平移，本次不扩。
- **命名**：~~整体改名 media 不在本次范围~~ → 已于 2026-11-16 随本分支落地：标识符与端点统一更名 signed media（`useSignedMedia`/`createMediaTicketService`/`/api/media/signed?ticket=`），机制命名债清偿，见 [图片签名直连](图片签名直连.md) 头部更名说明。

## 验证

- 服务端：`image-media-files.test.ts` 补音频签发成功 + 非 `audio/*`（如 .html）仍 415 拒签用例。
- 前端：`signedMediaPreview.test.tsx` 补"音频用签名 URL、不发 blob fetch"用例。
- 真机（部署后）：隧道点开 wav，播放器秒出、可边下边播。

## 风险

- 签名票据是短时（10 分钟）无鉴权凭证，放开到音频 = 持票者窗口内可读该音频文件。与图片同一信任模型，不新增信任面。
