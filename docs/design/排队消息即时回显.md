# 排队消息即时回显

> 状态：已完成。
> 基准：2.16.0 / 2026-10-28

## 目标与范围

排队消息被服务端确认发送后，当前会话立即显示对应用户消息。覆盖局域网 HTTP 页面缺少 Web Crypto 的环境；不改变排队、进程复用和服务端投递协议。

## 方案

在排队消息确认监听入口计算本地正文与附件的 SHA-256，继续只回显与服务端指纹一致的快照。使用可在普通 HTTP 页面运行的同步 SHA-256 实现，避免依赖仅在安全上下文可用的 `crypto.subtle`，也避免异步摘要期间回复先插入时间线。

## 验证

通过现有 `useQueuedMessageSync` 的事件订阅和消息回显接口，覆盖缺少 `crypto.subtle`、缺少 `crypto`、中文正文与附件、指纹不匹配、其他会话与旧确认帧。先运行失败测试，再修复；执行类型检查与构建。

验证结果：定向测试 11 项通过；类型检查、改动文件 lint 和前端构建通过。未进行真实手机上的 Claude 后台任务端到端验收。

## 风险

保留指纹核对，不能把本地后来追加的文字冒充已发送内容。同步计算只发生在排队消息发送确认时；附件仅参与元数据摘要，不读取文件内容。
