# 项目文件夹浏览器根目录约束

> 状态：已实施
> 基准：2.18.0 / 2026-11-11

## 目标

新建项目时的“Select Folder”对话框只以服务端工作区根（`WORKSPACES_ROOT`）为起点和上限：

- 打开时直接列出工作区根，路径栏显示真实绝对路径，不再显示 `~`。
- 工作区根下不出现 `..`，根目录本身不能作为项目目录。
- 工作区根的子目录仍可进入、选中、新建。

验收：桌面和手机打开弹窗，先看到工作区根的目录；根上“Use this folder”禁用，进入子目录后恢复；根上无 `..`。

## 范围

只改前端 `src/modules/project-creation-wizard/FolderBrowserModal.tsx` 与 `utils/workspaceApi.ts` 的浏览入口。服务端已经用 `validateWorkspacePath` 拒绝工作区根之外的路径，且把 `~` 映射为工作区根，本次不动后端。

## 方案

1. 打开弹窗时发不带路径的浏览请求（`browseFilesystemFolders(null)`），响应里的绝对路径就是工作区根。
2. 记录根路径；只有当前目录不是根时才显示 `..`。
3. 当前目录尚未加载成功、或就是根时，“Use this folder”禁用。
4. 路径栏只显示已加载的真实路径，加载中或失败时不显示 `~` 这类伪路径。

## 验证

- 新增组件测试：根不显示 `..`、按钮禁用；进入子目录后出现 `..`、按钮可用；点 `..` 回到根。
- `npx vitest run src/modules/project-creation-wizard/tests/FolderBrowserModal.test.tsx`
- `npm run typecheck`
- `npm run lint:client`

## 风险

- 工作区根本身不能再被选为项目目录。这是有意的：它通常是所有项目的父目录。
- 路径输入联想等其他 `browseFilesystemFolders` 调用仍传字符串，不受影响。
