# 命令弹窗即时打开

> 状态：已实施（2026-11-09）
> 目标：点 token 用量按钮、输入 `/cost` `/help` `/models` `/status` 时，弹窗立即出现；慢网下不再让人以为没点到。

## 问题

这四个内置命令都走 `POST /api/commands/execute`，前端等服务端回包后才 `setCommandModalPayload`。外网慢时，这一个往返就要几秒，期间界面没有任何反应。

`/cost` 还有一个串行等待：弹窗里的配额卡在弹窗挂载后才发 `/api/providers/:provider/quota`。弹窗晚开几秒，配额请求也晚发几秒，总等待是两个往返相加。

回包也没有和"这一次点击"绑定。用户等不及关掉弹窗、或者以为没点到去做别的事，旧回包到了照样弹出弹窗，并用旧数据覆盖输入框旁的 token 数。

服务端处理这条请求很轻（读会话行、必要时读一次用量快照），没有同步阻塞；慢在网络往返，不在服务端。

## 方案

`useChatComposerState.executeCommand` 识别这四个内置弹窗命令，发请求前先打开弹窗：

- 弹窗负载带 `pending: true`。
- `/cost` 先用前端已有的数据填充：当前引擎、当前模型、输入框旁的 token 用量。弹窗一挂载，配额请求随即发出，和 `/cost` 请求并行。
- `/help` `/models` `/status` 前端没有可用数据，弹窗正文显示加载状态。

每次打开分配一个请求序号。回包只在序号仍然有效时生效：

- 成功：用服务端结果替换负载，`pending` 置为 `false`；`/cost` 照旧同步输入框旁的 token 数。
- 失败：`/cost` 保留已显示的本地数据，只结束加载状态；其他命令关闭弹窗，在对话里追加错误消息（与原行为一致）。
- 用户关闭弹窗即作废序号，迟到的回包不再弹窗，也不改 token 数。

`/cost` 弹窗在 `pending` 且本地没有用量时，用量区显示"正在读取会话用量"，不显示 0。

## 范围

- `src/modules/chat/hooks/useChatComposerState.ts`：弹窗负载类型、`executeCommand`、`closeCommandModal`。
- `src/modules/chat/modals/CommandResultModal.tsx`：`pending` 的加载展示。
- 文案：`chat` 命名空间新增加载提示，简体、繁体、英文登记，其他语言回退英文。

不改服务端接口。

## 验证

- 钩子测试：点击后在回包前弹窗已打开且带本地数据；回包后替换；关闭后迟到回包不生效；`/cost` 失败保留数据，其他命令失败关闭并报错。
- 弹窗渲染测试：`pending` 时显示加载提示。

## 风险

- 本地 token 数与服务端补齐后的数可能短暂不同，回包后以服务端为准，数值会跳一次。
- 自定义命令（展开成消息再发送）仍要等回包才填入输入框，本次不改。
