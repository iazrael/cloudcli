# 聊天刷新回放顺序

> 基准：2.23.0 / 2026-11-16
> 状态：已实现并验证

## 目标与范围

修复刷新聊天时，最近一页历史与跨轮次回放混合，导致早期回答、旧错误出现在最新提问之后的问题。只调整无已确认游标的新页面订阅；保留已有游标的断线补发和会话跨轮次序号。

## 方案

服务端记录每轮开始前的会话序号。支持新基线的新页面（显式声明 replayScope=current_run、无 streamEpoch 且 lastSeq 为 0）订阅运行中的会话时，以本轮开始前的序号为回放起点，在确认帧可选字段 replayAfterSeq 中声明该基线。已完成轮次由 REST 分页历史承载。客户端仅在初次建立代次且游标为 0 时接受这一基线，随后逐条连续应用当前轮事件；窗口缺失仍走已有历史恢复。带游标的重连不截断跨轮次回放。

## 验证

通过现有 WebSocket 订阅接口测试跨轮刷新不回放旧答案与错误、当前轮未落盘文字仍被补发、旧游标重连仍补齐跨轮事件。通过 SessionTimelineStore 公共入口验证最近页历史与带基线确认、当前轮流式文字合并后的顺序，以及非法基线和缺口处理。运行相关模块测试、类型检查、构建和 lint。

## 风险

确认帧新增可选字段，旧页面未声明能力时保留原回放路径，新页面连接旧服务端也沿用原协议。仅初始订阅使用新基线，不通过时间或文本猜测身份，不清空会话缓冲，不改生产进程。
