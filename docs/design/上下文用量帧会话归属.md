# 上下文用量帧的会话归属

- 状态：已实施（2026-11-23）
- 基准：main @ 50bbc61b

## 目标

新会话（草稿态，尚未发送任何消息）的输入框不应显示任何上下文用量徽标；
任何会话视图只显示自己会话的用量。

## 问题

`useChatRealtimeHandlers` 处理 `status` / `token_budget` 帧时未校验
`directive.sessionId`，直接写入共享的 `tokenBudget` state。其他分支
（`complete`、`permission_request`、`background_tasks`）都按会话 id 过滤，
唯独这一帧不按。

后果：任意一个正在运行的会话（实测为运行中的 Codex 会话，每条
`thread/tokenUsage/updated` 事件都推一帧）会把它的用量灌进当前视图，
包括没有任何会话的“新会话”页——用户选完模型就看到 “429K / 475K”
徽标（数值即那个运行中会话的 `last_token_usage` 与
`model_context_window`，已与其 rollout 文件核对一致）。

## 方案

在 `token_budget` 分支加归属守卫，与其他分支同一模式：

```ts
if (directive.sessionId === activeViewSessionIdRef.current) {
  setTokenBudget(...);
}
```

帧不带 sessionId 时，store 的 `fallbackSessionId` 已把它补成当前视图
会话 id，判断自动通过，旧行为（运行中会话视图收到早期无 id 帧）不变；
只有“帧属于别的会话”这一种情况被丢弃。

## 范围

- `src/modules/chat/hooks/useChatRealtimeHandlers.ts`（一处守卫）
- `src/modules/chat/tests/`（归属测试）

## 验证

- 新增测试：他帧丢弃、本会话帧应用、无 id 帧应用（fallback 语义）。
- `npm run test:client`、`npm run typecheck`、`npm run lint`。

## 风险与已记录未修

- 会话切换竞速：`fetchFromServer`/`fetchMore` 回调里的
  `syncPaginationFromSlot` 未复核发起会话，慢速旧请求理论上可把旧会话
  的分页/用量短暂带入新视图（随后被新会话自己的加载覆盖）。与本次
  用户可见现象无证据关联，不在本修复内改动。
