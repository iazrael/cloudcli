# 插件安装：生产环境构建依赖与 node-pty 原生模块

> 状态：已实施；专项测试与真实终端插件安装验证通过，待构建、重启生产服务后生效
> 基准：2.17.0 / 2026-11-02

## 问题

在设置 → 插件里安装官方推荐的终端插件
`https://github.com/iazrael/cloudcli-plugin-terminal` 返回 `Internal server error`，同一操作在 Windows 上可用。

生产服务由 PM2 以 `NODE_ENV=production` 启动。插件安装执行
`npm install --ignore-scripts`，npm 把 `NODE_ENV=production` 当作 `--omit=dev`，跳过插件的
devDependencies。终端插件的 `build` 脚本是 `tsc`，而 TypeScript 只在 devDependencies，于是构建以
`tsc: not found` 失败。

失败本身只是普通 `Error`，`server/index.ts` 的全局错误中间件只对 `AppError` 输出 code 和 message，
其余统一回 500 `INTERNAL_ERROR` / `Internal server error`，界面因此看不到原因。

修好安装后，Linux 还有运行期问题：终端插件依赖 `node-pty@^1.1.0`，该版本的 npm 包只带
darwin / win32 预编译二进制；`--ignore-scripts` 又跳过了它的 install 脚本。
`require('node-pty')` 找不到 `prebuilds/linux-x64/pty.node`，插件服务启动即退出。Windows 有预编译，
所以之前可用。

## 方案

1. 插件依赖归插件：安装与更新固定执行
   `npm install --ignore-scripts --include=dev`，不受宿主 `NODE_ENV` 影响；与
   `scripts/self-update.mjs` 为宿主构建强制 devDependencies 的做法一致。
2. 补齐原生模块：安装后若存在 `node_modules/node-pty`，且当前平台既没有
   `build/Release/pty.node` 也没有 `prebuilds/<platform>-<arch>/pty.node`，执行
   `npm rebuild node-pty --ignore-scripts=false`。只运行这个已知包的 install 脚本
   （先检查预编译，再走 node-gyp），其他依赖的 postinstall 仍保持禁用；超时 180 秒。
3. 失败可读：install / update 中非 `AppError` 的失败包装成 `AppError`
   （`PLUGIN_INSTALL_FAILED` / `PLUGIN_UPDATE_FAILED`，500），消息带原始原因；git 失败已经是
   `AppError`，原样透传。日志仍由组合层记录，避免重复。

构建阶段（`npm run build`）继续继承宿主环境，不强制 `NODE_ENV`：`vite build` 等工具自行决定产物模式。

## 验证

- 复现：在终端插件仓库副本中执行
  `NODE_ENV=production npm install --ignore-scripts && npm run build`，得到
  `sh: 1: tsc: not found`。
- 修复后：同一流程加 `--include=dev` 构建通过；无 Linux 预编译时执行
  `npm rebuild node-pty` 后可加载原生模块，`node dist/server.js` 输出
  `{"ready":true,...}`。
- 新增专项测试：
  - 在 `NODE_ENV=production` 下安装一个 devDependency 提供构建脚本、依赖项模拟
    node-pty 的 git 插件，确认 devDependencies 被安装、原生模块被重建、构建产物存在；
  - install / update 的 npm 或构建失败返回带 code 的 `AppError`，git `AppError` 不被二次包装。
- 回归：plugins 专项测试、`npm run typecheck`、`npm run lint`。

## 风险

- 安装插件会多装 devDependencies，磁盘和安装时间略增；这是插件自带构建脚本的前提。
- `npm rebuild node-pty` 需要 python3、make、C++ 编译器和 node-gyp 头文件（有网络或缓存）。
  缺失时安装会明确失败，而不是装上一个起不来的插件。
- 原生重建只针对 node-pty 这一个已确认的依赖，不放开整个依赖树的 postinstall。
