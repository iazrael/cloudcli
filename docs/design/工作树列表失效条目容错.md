# 工作树列表失效条目容错

状态:已实现,合入 main 85cf81e6(2026-11-22)

## 目标

目录已被删除的 worktree 登记(git 元数据残留,porcelain 标 `prunable`,实例:发版流水线留在 /tmp 的 rel-v2.2x.0)会让 `listWorktrees` 的 per-entry `git status` 以 ENOENT 失败,整个接口 reject,前端吞错后显示"没有工作树"。

## 方案

- `worktree-list.service.ts`:prunable 条目跳过目录内 git 调用(`changedFileCount` 置 0);`countChangedFiles` 加 `catch(() => 0)` 兜底,单条坏数据不再炸整个列表。
- `WorktreeDescriptor` / 前端 `WorktreeInfo` 透传 `isPrunable`;条目行显示"已失效"徽标,prunable 条目隐藏"打开"按钮(目录不存在必然失败),merge/remove 沿用现有禁用与错误反馈。
- AGENTS.md 发版流程补收尾:发布 worktree 在验证完成后删除,防止再留 prunable 登记。

## 验证

- `worktree-list.service.test.ts` 追加:prunable 条目不炸列表(0 改动数、isPrunable 透传)、非 prunable 条目 git 失败同样兜底。
- providers 无关;`npm test`(worktrees 套件)、typecheck、lint、build;前端 vitest 全量。
