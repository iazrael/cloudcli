# 查看器两处体验修复

状态：已实施，待部署验证

## 背景

用户在手机 PWA 上反馈两个问题（2026-11-15）：

1. 通过文件树打开工作区外部文件（`只读` 徽标场景，如 `/Volumes/External/Workspaces/...` 下的 README.md），未做任何编辑，关闭时每次都弹"您有未保存的更改"确认框。
2. 图片查看器打开长图（高大于宽的截图类图片）时，默认显示为宽度撑满、上下被裁切，无法一眼看到整图。

## 目标

- 外部只读文件打开即为"干净"状态：无脏标记圆点，关闭不弹确认；真实编辑后仍正常询问。
- 图片查看器默认完整显示整图（contain），长图不再溢出裁切；缩放/平移/双击/双指行为不变。

## 根因与方案

### 1. 外部只读文件打开即脏

`src/modules/code-editor/hooks/useCodeEditorDocument.ts` 的 `isReadOnlyExternal` 加载分支只调用了 `setContent(externalData.content)`，没有同步基线 `savedContent`（基线保持初始值 `''`），因此 `hasUnsavedChanges` 从打开那一刻就为 true；又因为只读文件禁止保存，该标记永远无法清除。其余加载路径都走 `applyLoadedContent`（同时设置 buffer 和基线），唯独这条分支漏了。

修复：外部分支改用 `applyLoadedContent`，并补上与其他路径一致的 `isStaleLoad()` 检查。

### 2. 长图溢出裁切

`src/shared/ui/ImageViewerSurface.tsx` 的图片外有一层 wrapper（`flex max-h-full max-w-full`）。容器用 `items-center` 居中，wrapper 高度为内容自适应（非 definite），img 的 `max-h-full`（百分比 max-height）相对自适应高度解析失效——只剩 `max-w-full` 生效：宽图宽度撑满、高度按原始纵横比溢出，被容器 `overflow-hidden` 裁掉上下两端。

已用浏览器实测复现：400×2400 长图在 420×669 容器中渲染为 400×2400（溢出 1731px）；把尺寸类直接放到 img 上后为 112×669，完整可见。

修复：去掉 wrapper，把 transform/过渡/背景色（backdrop）/will-change 直接移到 img 上。img 成为定高容器的直接 flex 子项后，`max-h-full` 正常解析，默认即 contain 完整显示；backdrop 从"贴图片的盒子"变为"图片元素盒"（两者在 contain 修复后重合），缩放/平移逻辑（仅依赖 containerRef）不受影响。

## 范围

- `src/modules/code-editor/hooks/useCodeEditorDocument.ts`（外部分支基线）
- `src/shared/ui/ImageViewerSurface.tsx`（渲染结构）
- `src/modules/code-editor/tests/unsavedChangesGuard.test.tsx`（新增外部只读用例）
- `src/shared/tests/`（如结构断言受影响则同步）

## 验证

- 新增测试：外部只读文件打开无脏标记、Escape 直接关闭不询问；真实编辑后仍询问。
- 既有守卫测试、UnifiedImageViewer/imageViewerMetadata 测试全绿。
- `npm run test:client`、`typecheck`、`lint`、`build:client`。
- 浏览器实测：dev 环境（SERVER_PORT/VITE_PORT）打开长图确认完整显示、缩放/双击/平移正常；外部只读文件无脏点、关闭不弹窗。

## 风险

- backdrop 视觉从"贴图盒子"变为"整高列"仅理论上存在于图片未占满容器时；修复后 img 元素盒等于绘制范围，实际两者重合，UnifiedImageViewer 白底模式行为不变。
- `window.confirm` 守卫逻辑本身不动，仅数据源修正，误放行风险低（有守卫测试兜底）。
