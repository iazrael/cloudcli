# 插件列表加载失败重试

状态：已完成（2026-11-19）

## 目标

插件列表（`/api/plugins`）在应用挂载时只加载一次，失败后列表静默置空：设置页所有插件推荐卡都显示「安装」按钮，已安装插件不可见，主页也不出现插件 tab；此时点「安装」会被服务端以「目录已存在」拒绝，用户无从判断原因。

让插件设置页在打开时重新拉取列表，并把加载失败展示给用户、提供重试入口。

## 范围

- `src/modules/plugins/PluginSettingsTab.tsx`：打开设置页时补拉一次列表；加载失败时显示错误与重试按钮。
- `src/modules/i18n/locales/{en,zh-CN,zh-TW}/settings.json`：新增 `pluginSettings.loadFailed`、`pluginSettings.retry`，其余语言走 en fallback。

不改 PluginsProvider 的初始加载语义，不改主页 tab 渲染逻辑。

## 方案

- `PluginSettingsTab` 从 `usePlugins()` 取 `refreshPlugins` 与 `pluginsError`，组件 mount 时调用 `void refreshPlugins()`。设置页 tab 是条件渲染（`Settings.tsx` 中 `activeTab === 'plugins' && <PluginSettingsTab />`），每次切到插件页都会重新 mount，即每次打开都补拉。
- `pluginsError` 非空时，在插件区块上方渲染一行错误提示 + 重试按钮（点击再次调用 `refreshPlugins`）。加载中（`loading`）仍显示现有 scanning 状态。
- install/uninstall/toggle/update 成功路径已有 `refreshPlugins`，无需重复。

## 验证

- `src/modules/plugins/tests/pluginGitErrors.test.tsx` 新增两个用例：
  1. 列表加载失败 → 显示失败提示与重试按钮；点重试成功后错误消失、已安装卡片出现。
  2. 打开设置页触发补拉：第一次 `/api/plugins` 失败、第二次成功 → 最终渲染出已安装插件。
- 跑窄测试 → `npm run test:client` → `npm run build:client` → `npm run typecheck` → `npm run lint`。

## 风险

- 打开设置页多一次列表请求：接口是本地磁盘扫描，开销可忽略。
- 补拉在 mount 时异步进行，短暂会显示旧列表后更新；与现有「操作后刷新」行为一致，无竞态（`refreshPlugins` 为串行 setState）。
