# 文件树创建/重命名重复提交

状态：已实现，刷新即生效（纯前端）

基准：main @ 2026-11-21

## 现象

新建文件/文件夹命名成功（成功 toast、条目已建）后，跟着弹一个 `Directory already exists` / `File already exists` 错误 toast。

## 根因

行内输入框的确认有两条通道：Enter 直接调 `handleConfirmCreate`，blur 经 100ms 兜底再调一次。Enter 触发后 `disabled={operationLoading}` 立即禁用输入框，浏览器随即触发 blur，100ms 兜底回调里 `operations.isCreating` 是旧闭包值（仍为 true），第二次确认发出重复请求：第一个成功、第二个撞服务端 409（`createEntry` 对已存在条目返回 `File/Directory already exists`）。`handleConfirmRename` 是同款结构，双触发会报 "File or directory not found"。

## 方案

`useFileTreeOperations` 加模块级防重入 ref（`confirmInFlightRef`）：创建与重命名的确认函数进入时置位、finally 复位，in flight 期间的再次调用直接返回。不依赖 state 闭包，blur 兜底、Enter、软键盘"完成"任意组合都只发一次请求。UI 结构与确认通道保持不变。

## 验证

- 新增 `src/modules/file-tree/tests/useFileTreeOperations.test.tsx`（renderHook + mock api）：
  in flight 期间第二次创建/重命名确认不发第二个请求、不弹错误 toast。
- 回归 file-tree 前端全套 + `test:client` + `build:client` + `typecheck`。

## 风险

- 防重入只拦"同一次命名的重复确认"，不同条目间操作互不影响（ref 在 finally 复位）。
