# 文件树按需加载

> 状态：已实施
> 核对基准：2.18.0 / 2026-11-08

## 目标

文件树改成"展开一层，加载一层"。项目再大也能打开，首屏只读根目录一层。

全量文件列表只用于"按名字找文件"，改由服务端搜索承担。前端不再一次拿到整个项目。

验收：

- SpaceWarrior4（过滤后 10,870 条）能正常打开文件树，搜索、@ 提及、命令面板、打开聊天里的文件引用都可用。
- 打开文件树只发一次请求，只读根目录一层；展开一个目录只读这个目录一层。
- 去掉整树接口和 1 万条上限。

## 现状与问题

`GET /api/file-tree/projects/:projectId/files` 一次递归读完整个项目（最多 10 层），每个条目调一次 `lstat`，整棵树放在内存里，再序列化成一个 JSON 返回。全树共用一个 10,000 条的计数，超过就返回 413（`server/modules/file-tree/file-tree.service.ts` 的 `MAXIMUM_FILE_TREE_ENTRIES`）。这个上限是上游为了防止"根目录设成家目录把服务端内存撑爆"加的（上游提交 `0f67810c`，#1082）。

整棵树有 4 个调用方：

| 调用方 | 用途 | 拿到整棵树后怎么用 |
|---|---|---|
| `file-tree/hooks/useFileTreeData.ts` | 文件树面板 | 渲染；搜索框在前端过滤整棵树 |
| `chat/hooks/useFileMentions.tsx` | 输入框 `@` 提及 | 拍平成列表，每次输入 `@` 重新拉一次整树，前端子串过滤取前 10 条 |
| `command-palette/hooks/useFilesSource.ts` | 命令面板文件页 | 拍平后只取前 500 个，交给 cmdk 过滤 |
| `project-workspace/hooks/useFileOpenResolver.ts` | 打开聊天里的相对路径或文件名 | 拍平后按路径后缀、再按文件名匹配 |

问题：

1. **大项目整个不可用。** 超过 1 万条时，文件树报错；其他三个调用方遇到非 2xx 响应直接返回空列表，@ 提及、命令面板、引用解析一起静默失效。
2. **成本随项目总量增长，和用户看了什么无关。** 用户只看根目录，也要付出整个项目的 `lstat`、内存和传输开销，手机上尤其明显。@ 提及每按一次 `@` 就重新拉一次整树。
3. **忽略规则不完整。** 只读根目录的 `.gitignore`，不读子目录的 `.gitignore`，也不读 `.git/info/exclude`。根目录有 `.gitignore` 时，`dist`、`vendor` 这些内置跳过名单也会失效。
4. **命令面板搜不全。** 只取遍历顺序里的前 500 个文件，后面的文件搜不到。

实测（SpaceWarrior4，本机）：现行过滤规则下整树 10,870 条；`rg --files --hidden` 列出全部可见文件用时 0.06 秒，嵌套 `.gitignore` 生效。

### 1. 目录接口：一次读一层

`POST /api/file-tree/projects/:projectId/directories`

请求体 `{ "paths": string[] }`，一次最多 50 个。路径可以是相对项目根的路径（空串表示根目录），也可以是项目内的绝对路径。用 POST 是为了批量：刷新和定位都要一次读多个目录。

响应按请求顺序返回数组，单个目录出错不影响其他目录：

```jsonc
{
  "directories": [
    { "request": "", "path": "/abs/project", "entries": [/* FileTreeNode，无 children */], "truncated": false },
    { "request": "src/gone", "error": { "code": "FILE_TREE_PATH_NOT_FOUND", "message": "..." } }
  ]
}
```

- `entries` 沿用现有 `FileTreeNode` 结构（名称、绝对路径、类型、大小、修改时间、权限、`isSymlink`），不带 `children`。按"目录在前、名称排序"返回。
- **单目录上限 5,000 条。** 超过时停止读取，返回已读到的部分并标记 `truncated: true`，前端在该目录末尾提示"仅显示前 5,000 项"。目录仍用流式读取（现有 `openDirectory`），一个目录里有上百万个文件也不会全部读进内存。
- **路径校验是安全边界。** 目标路径和项目根都先做 `realpath`，再做前缀比较。项目外的路径、`../` 越界、指向项目外的符号链接一律返回 403。不读项目外的目录。
- 符号链接沿用现行行为：作为条目显示并标记 `isSymlink`，但不当作目录展开，避免循环和越界。
- 系统伪文件系统（`FORBIDDEN_WORKSPACE_PATHS`，如 `/proc`）照旧不读。
- 元数据 `lstat` 沿用现有并发限制器。

### 2. 忽略规则：逐级生效

目录接口和搜索接口用同一套规则，两边看到的文件一致：

- 永远排除：`node_modules`、`.git`、`.svn`、`.hg`（现有硬排除）。
- 读取规则文件：项目根的 `.git/info/exclude`，以及从项目根到目标目录每一级的 `.gitignore`。每个文件的规则相对它所在的目录生效，下层规则覆盖上层规则（含 `!` 取反）。实现用现有依赖 `ignore` 包的 `test()`，它能区分"被忽略"和"被取反放行"。
- 项目根没有 `.gitignore` 时（多数是非 git 项目），套用内置跳过名单（`dist`、`build`、`vendor`、`.venv` 等，即现有 `IGNORED_DIRECTORY_NAMES`）。
- 不读 `.ignore`、`.rgignore`，不读项目根以上的规则文件，也不读用户全局的 gitignore。
- 规则文件每次请求现读。同一批请求里的多个目录共用读到的规则，每个文件只读一次；层数有限，开销很小。

`respectGitignore` 参数取消，忽略规则总是生效。现在唯一的调用方本来就总是传 `true`。

### 3. 搜索接口：服务端查文件索引

`GET /api/file-tree/projects/:projectId/files/search?q=<关键词>&limit=<条数>&type=<file|any>`

- **索引**：调用项目已有依赖 `@vscode/ripgrep` 执行 `rg --files --hidden --no-require-git --no-ignore-dot --no-ignore-global --no-ignore-parent`，再加上述硬排除和内置跳过名单的 `--glob`，得到项目内全部可见文件的相对路径。目录不单独列出，从文件路径的上级目录推出来；空目录搜不到，可以接受。
- **缓存**：按项目根缓存在内存，15 秒内复用；同一项目同时发起的构建只跑一次 `rg`。最多缓存 8 个项目，超过时淘汰最久没用的。本模块的写操作接口（新建、重命名、删除、上传、保存）成功后，清掉该项目的缓存。
- **规模上限**：索引最多 20 万个文件。超过时停止 `rg`，用已读到的部分，响应带 `indexIncomplete: true`，前端提示"项目过大，搜索结果可能不全"。
- **匹配与排序**：不区分大小写，关键词按空白切成多个词，每个词都要出现在相对路径里。排序：文件名完全相等 > 文件名前缀 > 文件名包含 > 只在路径里命中；同级比较时短路径排前面。
- **结果**：默认最多 50 条，最大 200 条，只对返回的结果调 `lstat` 补齐元数据。结构是 `FileTreeNode` 加 `relativePath`，另带 `truncated`（命中数超过 limit）和 `indexIncomplete`。`type=file` 只返回文件，`any` 同时返回推出来的目录。
- `rg` 启动失败或异常退出时返回 500 并记录日志，前端显示搜索失败。不退回整树遍历。

### 4. 前端改造

**文件树面板（`src/modules/file-tree`）**

- 用"目录缓存"取代 `files` 数组：`Map<目录绝对路径, { status: 'loading' | 'loaded' | 'error' | 'stale', entries, truncated }>`。渲染时，展开的目录从缓存里取子项。
- 打开面板时只请求根目录。点击未加载的目录时先展开并显示加载中，拿到数据后显示子项。加载失败时在该目录下显示错误和重试按钮。
- 所有目录都显示展开箭头（不额外读一层去判断是否为空）；展开后发现是空目录，就显示"空文件夹"。
- **刷新**（刷新按钮，以及新建、重命名、删除、上传成功后）：一次批量请求重读根目录和当前展开链上已加载的目录；已加载但收起的目录标成 `stale`，下次展开时再读。刷新后不存在的目录从缓存和展开集合里删除。
- **定位目录**（聊天里点击 `path/` 引用，或点击搜索结果里的文件夹）：把引用拆成从根开始的各级相对路径（`revealRequestPaths`），一次批量请求读出来，逐级核对上一级的列表里确实有这个目录，展开到最后一级可见的目录，再把它滚动到视图中间。
- **搜索框**：输入后防抖 150ms 调搜索接口（`type=any`，`limit=200`），新请求会取消旧请求。结果按路径拼成一棵局部树，全部展开显示，和现在过滤整棵树的效果一致。右键菜单、重命名、打开文件照常可用，因为节点带有绝对路径和元数据。清空搜索后回到按需加载的树，展开状态保持不变。
- 切换项目时清空目录缓存和展开集合。

**@ 提及（`useFileMentions`）**：输入 `@` 后的关键词按 100ms 防抖调搜索接口（`type=file`，`limit=20`），取消旧请求，显示前 10 条。去掉"每次按 `@` 拉整树"。

**命令面板（`useFilesSource`）**：按输入关键词防抖 150ms 调搜索接口（`type=file`，`limit=50`）。cmdk 只能整体关闭客户端过滤，所以文件条目把当前搜索词作为 `keywords` 传给 cmdk，让它把服务端已匹配的结果算作命中。没有输入时显示服务端按路径排序的前 50 个。

**引用解析（`useFileOpenResolver`）**：用引用的文件名调搜索接口（`type=file`，`limit=200`），对返回结果套用现有的 `findBestMatch`（先后缀匹配，再文件名匹配）。去掉按项目缓存整棵树。

**API 层（`src/shared/api.ts`）**：去掉 `getFiles`，新增 `listDirectories(projectId, paths)` 和 `searchFiles(projectId, params)`。

### 5. 删除的内容

- 服务端：`GET /files` 路由、`listProjectFiles`、递归的 `buildFileTree`、`MAXIMUM_FILE_TREE_ENTRIES` 和 `FILE_TREE_TOO_LARGE` 错误。
- 前端：4 处拍平整树的函数，`useFileTreeSearch` 里对整棵树的过滤。

## 不做的事

- 不做文件变化监听推送。文件树和现在一样靠手动刷新和操作后刷新。
- 不做长列表虚拟滚动。单目录 5,000 条的上限先挡住极端情况，真不够用再单独做。
- 不改文件读写、上传、图片签名等其他接口。
- 不做模糊匹配（子序列匹配），只做多词子串匹配。

## 验证

**服务端单测**（`server/modules/file-tree/tests`）

- 目录接口：只返回一层；排序；单目录截断；批量里一个出错其他照常；批量超过 50 个返回 400。
- 忽略规则：根和子目录的 `.gitignore`、`.git/info/exclude`；`.ignore` 不生效；下层取反覆盖上层；硬排除；无规则文件时套用内置名单。
- 路径安全：`../` 越界、项目外绝对路径、指向项目外的符号链接目录，都返回 403；项目根本身是符号链接时能正常读。
- 搜索：排序规则；多词匹配；`type` 过滤；目录推导；limit 和 `truncated`；索引上限和 `indexIncomplete`；缓存复用、并发只构建一次、写操作后失效；`rg` 失败返回 500。

**前端单测**：展开时按需请求、失败重试、刷新只重读展开链、收起的目录标为 stale、定位一次批量请求、搜索防抖和取消旧请求；@ 提及、命令面板、引用解析改用搜索接口后的行为。

**实际运行**：在工作树里用临时数据库启动 dev（`env -i` 并显式指定 `DATABASE_PATH`，不碰生产库），添加 SpaceWarrior4 项目，在手机宽度下检查：文件树能打开，展开 `assets` 正常，搜索能找到深层文件，@ 提及和命令面板能搜到文件。在网络面板确认打开面板只发一次目录请求。

**审查**：按 L2 执行。新的目录接口接受路径参数，属于安全边界，交付前对路径校验部分做一次独立审查。

## 风险

- **前后端版本不一致。** 部署后，没刷新的旧页面还在调 `GET /files`，会拿到 404，文件树报错，刷新页面后恢复。这是单人自用实例，可以接受，不保留旧接口。
- **规则和 git 不完全一致。** 不读全局 gitignore；目录接口和 `rg` 对极少见的规则写法可能理解不同。影响只是个别文件显示与否，不涉及安全。
- **引用解析的召回。** 同名文件超过 200 个时，后缀匹配可能漏掉正确的那个。现实中极少见。
- **搜索结果的新鲜度。** 外部改动（终端、引擎写文件）最多有 15 秒看不到。本模块自己的写操作会立即清缓存。
