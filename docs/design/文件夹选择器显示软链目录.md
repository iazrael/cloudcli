# 文件夹选择器显示软链目录

状态：已实现，配置侧待用户执行（见"方案"第 2 点）

基准：main @ 2026-11-21

## 目标

项目创建向导的"选择文件夹"弹窗与工作区路径补全（同一端点）能列出指向目录的软链，断链与指向文件的软链不出现。

## 现状与根因

- `browseWorkspace`（`server/modules/file-tree/file-tree.service.ts`）用 `entry.isDirectory()` 过滤 `fs.opendir` 的 Dirent；软链条目 `isDirectory()` 为 false，指向目录的软链全部被滤掉。
- 只改显示不够：浏览子目录与项目注册都要过 `validateWorkspacePath`（`server/shared/utils.ts`），它 realpath 后要求落在工作区根内。软链目标（如外置卷）在根外会被 403——现状下路径栏手动输入软链路径同样被拒。

## 方案

1. **显示（本仓代码）**：`browseWorkspace` 对 `isSymbolicLink()` 条目用 `stat`（跟随软链）确认解析为目录才收集；stat 失败（断链/不可读）跳过。安全面零扩大：列表只多暴露名字，点击展开与选中注册仍由 `validateWorkspacePath` 把关（项目文件树 `listDirectories` 不跟随逃逸软链的语义不变，那是读取面防线，与此处的"候选名单"不同）。
2. **配套配置（部署侧，需用户执行）**：`~/.pm2/ecosystem.config.cjs` 把 `WORKSPACES_ROOT: '/Users/azrael/workspaces'` 换成 `WORKSPACES_ROOTS: '/Users/azrael/workspaces:/Volumes/Extenal/Workspaces'`，然后 `pm2 restart cloudcli && pm2 save`。多根校验是 `WORKSPACES_ROOTS` 的既有设计（realpath 后任一根内即放行），不改校验代码、不动权限边界。
3. 不采用代码级"软链豁免"：那是 `validateWorkspacePath` 权限判定改动（任何根内软链可指根外任意处），L3 且影响所有部署。

## 验证

- `server/modules/file-tree/tests/file-tree.service.test.ts` 新增真实文件系统用例：目录软链列出、断链与文件软链跳过。
- 既有 browseWorkspace 用例回归。

## 风险

- 每个软链条目一次 `stat`，目录内大量软链时浏览变慢（本地盘可忽略；5000 条上限不变）。
- Windows 创建 symlink 需要开发者模式；测试已有 symlink 用例先例，CI 环境一致。
