Usage Patterns

Programmatically trigger AI agents to work on projects, then inspect, continue or stop the resulting session. Start a long run without holding the request open, follow its events from a cursor, and read the final reply from the stored transcript. Clone GitHub repositories or use existing project paths. Perfect for CI/CD pipelines, automated code reviews, and bulk processing.

Authentication

All API requests require authentication using an API key in the X-API-Key header.

Generate API keys in Settings → API & Tokens.

GitHub Credentials

For private repositories, store a GitHub token in settings or pass it with each request.

Note: GitHub tokens in the request override stored tokens.

Authentication Header

X-API-Key: ck_your_api_key_here

Agent

POST http://localhost:3001/api/agent

Trigger an AI agent (Claude, Cursor, Codex, or OpenCode) to work on a project.

Request Body Parameters

Parameter Type Required Description
githubUrl string Conditional GitHub repository URL to clone. If path exists with same repo, reuses it. If path exists with different repo, returns error.
projectPath string Conditional Path to existing project OR destination for cloning. If omitted with githubUrl, auto-generates path. If omitted with sessionId, uses the session's own project path. If used alone, must point to existing project directory.
sessionId string Optional Continue an existing session: the sessionId (or providerSessionId) an earlier response reported. When this alone identifies the target, projectPath and githubUrl may be omitted. A session already running returns 409; an unknown id returns 404. Omitted: a new session is created.
message string Required Task for the AI agent
provider string Optional claude, cursor, codex, opencode, zcode, or antigravity (default: claude)
stream boolean Optional Enable streaming (default: true)
wait boolean Optional Wait for the run to finish (default: true). false answers 202 immediately with the app session id and the run's runId; poll GET /api/agent/:sessionId for status, GET /api/agent/runs/:runId/events for progress and GET /api/agent/:sessionId/result for the reply. stream is ignored in this mode and createBranch/createPR are refused.
clientRequestId string Optional Idempotency key for a new session. A retry with the same value resolves to the session the first attempt allocated; a wait:false retry that lands while the original run is still going also gets that run back instead of a second dispatch.
model string Optional Model identifier for the AI provider:

Anthropic (claude): default, opus, fable, sonnet, haiku (default: default)

OpenAI (codex): gpt-6.2-sol, gpt-6.2-astra, gpt-6.1-sol, gpt-6.1-terra, gpt-6-astra (default: gpt-6.2-sol)

Cursor: auto, composer-2.5-fast, composer-2.5, claude-opus-5, claude-sonnet-5 (default: auto)

OpenCode: opencode-go/beam-free, opencode-go/claude-haiku-5-5, opencode-go/qwen3.8-flash (default: opencode-go/beam-free)

ZCode: GLM-5.3 (default: GLM-5.3)

Antigravity: gemini-4-argon, gemini-4-neon, gemini-4-hydrogen, claude-opus-5-5, claude-sonnet-5-5 (default: gemini-4-argon)
effort string Optional Reasoning effort for Claude, Codex, OpenCode, ZCode, and Antigravity models that expose effort metadata. Use default or omit it to let the provider decide.
unattended boolean Optional Claude only (default: true). While true, a form an MCP server sends mid-call is declined at once. Pass false when a person will watch the run in the UI: the form then appears in any tab that opens the session and waits for an answer there.
cleanup boolean Optional Auto-cleanup after completion (default: true). Only applies when cloning via githubUrl. Existing projects specified via projectPath are never cleaned up.
githubToken string Optional GitHub token for private repos
branchName string Optional Custom branch name to use. If provided, createBranch is automatically enabled. Branch names are validated against Git naming rules. Works with githubUrl, projectPath, or sessionId (if the project has a GitHub remote).
createBranch boolean Optional Create a new branch after successful completion (default: false). Automatically set to true if branchName is provided. Works with githubUrl, projectPath, or sessionId (if the project has a GitHub remote).
createPR boolean Optional Create a pull request after successful completion (default: false). PR title and description auto-generated from commit messages. Works with githubUrl, projectPath, or sessionId (if the project has a GitHub remote).
Path Handling Behavior:

Scenario 1: Only githubUrl → Clones to auto-generated temporary path
Scenario 2: Only projectPath → Uses existing project at specified path
Scenario 3: Both provided → Clones githubUrl to projectPath
Scenario 4: Only sessionId → Continues in the session's own project path

Validation: If projectPath exists and contains a git repository, the remote URL is compared with githubUrl. If URLs match, the existing repo is reused. If URLs differ, an error is returned.

Response (Streaming)

Server-sent events (SSE) format with real-time updates. Content-Type: text/event-stream

The first events include session-id (the app session id to pass back as sessionId) and status. Provider events follow with their own kind, seq and sessionId.

Response (Non-Streaming)

JSON object containing session details, assistant messages only (filtered), and token usage summary. Content-Type: application/json

Each entry in messages is a normalized text event from the run. Providers that stream their reply as deltas (OpenCode) are assembled into one such event, so the response carries the reply either way.

Response (wait: false)

HTTP 202 with JSON. The provider keeps running after the response; the body carries the ids the follow-up reads need:

{
  "success": true,
  "sessionId": "abc123",
  "provider": "opencode",
  "providerSessionId": null,
  "projectPath": "/path/to/project",
  "status": "running",
  "run": {
    "runId": "8f14e45f-ea2a-4f3b-b8d1-9b5c1c2e7a10",
    "startedAt": "2026-11-22T12:00:00.000Z",
    "lastSeq": 0
  }
}

Pass run.lastSeq as the initial after cursor of the events endpoint, and sessionId back as sessionId to continue the conversation.

Error Response

Returns error details with appropriate HTTP status code.

Session Lifecycle

Every response reports its app session id. Use it — or the provider-native providerSessionId — to inspect, continue or stop the session. A wait:false run also reports a runId, the cursor for its event page. Closing the stream does not stop the run; send an explicit abort.

GET http://localhost:3001/api/agent/:sessionId

Reports whether a turn or background work is still running.

Response

{
  "success": true,
  "sessionId": "abc123",
  "provider": "claude",
  "providerSessionId": "ses_9f2c...",
  "projectPath": "/path/to/project",
  "name": "Fix authentication bug",
  "archived": false,
  "status": "running",
  "run": {
    "runId": "8f14e45f-ea2a-4f3b-b8d1-9b5c1c2e7a10",
    "startedAt": "2026-11-14T12:00:00.000Z",
    "lastSeq": 12
  },
  "createdAt": "2026-11-14T11:59:00.000Z",
  "updatedAt": "2026-11-14T12:00:10.000Z"
}

status is running while a turn is active, background while only background work remains, and idle otherwise. run is null unless a turn is running.

GET http://localhost:3001/api/agent/:sessionId/result

The assistant reply of the last turn, read from the stored transcript. This is the read side of wait:false: poll the status route until idle, then read the reply here. Unlike the live event buffer it survives a dropped connection and a server restart.

Query Parameters

Parameter Type Required Description
limit integer Optional Size of the history tail page to read (default 200, max 1000). The last user text in that page anchors the turn, so a continued session returns only its latest reply.

Response

{
  "success": true,
  "sessionId": "abc123",
  "provider": "opencode",
  "providerSessionId": "ses_9f2c...",
  "projectPath": "/path/to/project",
  "status": "idle",
  "run": null,
  "messages": [
    {
      "kind": "text",
      "role": "assistant",
      "content": "I've completed the task..."
    }
  ],
  "reply": "I've completed the task...",
  "tokens": { "inputTokens": 150, "outputTokens": 50 }
}

While status is running or background, messages/reply may be empty or partial; treat idle as the final answer. Unknown session: 404.

GET http://localhost:3001/api/agent/runs/:runId/events

One run's buffered events after a cursor. Poll with after set to the previous response's lastSeq to continue a run after a dropped connection or a killed request; stop when terminal is true.

Query Parameters

Parameter Type Required Description
after integer Optional Return events whose seq is greater than this value. Start with the run's run.lastSeq from the wait:false response so earlier turns are skipped; default 0.

Response

{
  "success": true,
  "runId": "8f14e45f-ea2a-4f3b-b8d1-9b5c1c2e7a10",
  "sessionId": "abc123",
  "provider": "opencode",
  "status": "running",
  "terminal": false,
  "events": [
    { "kind": "text", "seq": 7, "content": "Analyzing the project..." }
  ],
  "lastSeq": 7,
  "replayFromSeq": 1,
  "streamEpoch": "…",
  "stale": false
}

stale: true means the cursor predates the replay buffer (5000 events / about 5 minutes); the middle was dropped and the caller should use /result instead. A completed run stays readable for about 5 minutes, then this route returns 404; the persisted /result is the authoritative answer.

POST http://localhost:3001/api/agent/:sessionId/abort

Stops the running turn or the remaining background work, using the same path as the UI's stop button. An idle session returns aborted: false, so retries are safe.

Response

{
  "success": true,
  "sessionId": "abc123",
  "aborted": true
}

Unknown session: 404. Provider refused to stop: 409. The original POST /api/agent request then ends with success: false, aborted: true (or a status event in streaming mode).

Get Session Status

curl http://localhost:3001/api/agent/abc123 \
  -H "X-API-Key: ck_..."

Start Without Waiting

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "projectPath": "/path/to/project",
    "provider": "opencode",
    "message": "Run the long task",
    "wait": false,
    "clientRequestId": "long-task-1"
  }'

Read a Run's Events

curl "http://localhost:3001/api/agent/runs/8f14e45f-ea2a-4f3b-b8d1-9b5c1c2e7a10/events?after=0" \
  -H "X-API-Key: ck_..."

Read the Final Result

curl "http://localhost:3001/api/agent/abc123/result?limit=200" \
  -H "X-API-Key: ck_..."

Abort a Run

curl -X POST http://localhost:3001/api/agent/abc123/abort \
  -H "X-API-Key: ck_..."

Abort Response

{"success":true,"sessionId":"abc123","aborted":true}

Continue a Session

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "sessionId": "abc123",
    "message": "Now add tests",
    "stream": false
  }'

Provider Models

GET http://localhost:3001/api/providers/:provider/models

Query the supported models, catalog default, and available reasoning-effort levels for a specific AI provider (claude, codex, cursor, opencode, zcode, or antigravity).

The returned models.DEFAULT or any model value in models.OPTIONS can be passed directly as model to POST /api/agent. The values in models.EFFORT_LEVELS (such as low, medium, high, max) can be passed as effort.

Path Parameters

Parameter Type Required Description
provider string Required Provider identifier: claude, codex, cursor, opencode, zcode, or antigravity.

Authentication

Supports either X-API-Key: ck_... header (for CI / Agent scripts) or Authorization: Bearer <token>.

Query Provider Models

curl "http://localhost:3001/api/providers/claude/models" \
  -H "X-API-Key: ck_..."

Sample Response

{
  "success": true,
  "data": {
    "provider": "claude",
    "models": {
      "OPTIONS": [
        { "value": "default", "label": "Default (recommended)" },
        { "value": "opus", "label": "Opus 5.5" },
        { "value": "sonnet", "label": "Sonnet 5.5" }
      ],
      "DEFAULT": "default",
      "EFFORT_LEVELS": ["low", "medium", "high", "xhigh", "max"]
    }
  }
}

Usage Patterns

Clone and Process Repository

Clone a repository to an auto-generated temporary path and process it.

Use Existing Project

Work with an existing project at a specific path.

Clone to Specific Path

Clone a repository to a custom location for later reuse.

CI/CD Integration

Integrate with GitHub Actions or other CI/CD pipelines.

Create Branch and Pull Request

Automatically create a new branch and pull request after the agent completes its work. Branch names are auto-generated from the message, and PR title/description are auto-generated from commit messages.

Use Existing Project

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "projectPath": "/home/user/my-project",
    "message": "Refactor database queries"
  }'

Clone to Custom Path

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "githubUrl": "https://github.com/user/repo",
    "projectPath": "/tmp/my-location",
    "message": "Review security",
    "cleanup": false
  }'

CI/CD (GitHub Actions)

- name: Trigger Agent
  run: |
    curl -X POST ${{ secrets.API_URL }}/api/agent \
      -H "X-API-Key: ${{ secrets.API_KEY }}" \
      -H "Content-Type: application/json" \
      -d '{
        "githubUrl": "${{ github.repository }}",
        "message": "Review for security",
        "githubToken": "${{ secrets.GITHUB_TOKEN }}"
      }'

Create Branch and PR

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "githubUrl": "https://github.com/user/repo",
    "message": "Fix authentication bug",
    "createBranch": true,
    "createPR": true,
    "stream": false
  }'

Custom Branch Name

curl -X POST http://localhost:3001/api/agent \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ck_..." \
  -d '{
    "githubUrl": "https://github.com/user/repo",
    "message": "Add user authentication",
    "branchName": "feature/user-auth",
    "createPR": true,
    "stream": false
  }'

Branch & PR Response

{
  "success": true,
  "branch": {
    "name": "feature/user-auth",
    "url": "https://github.com/user/repo/tree/feature/user-auth"
  },
  "pullRequest": {
    "number": 42,
    "url": "https://github.com/user/repo/pull/42"
  }
}
